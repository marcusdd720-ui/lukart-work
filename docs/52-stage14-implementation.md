# Stage 14 — UNIVERSUM Execution Kernel — Implementation

Status: IMPLEMENTED / BUILDER VERIFICATION ONLY

The kernel lives in lukart_work/factory/universum.py and is intentionally pure:
no network, no GitHub mutation, no CASE state mutation, and no independent approval.

Implemented contracts:
LiveStateRestore, DeltaClassifier, CriticalPathPlanner, FailureClassifier,
CandidateFreeze, CIBudget, ClosureBundlePlanner, SupersessionAnalyzer,
EvidenceReusePolicy, NextActionResolver, HumanGateResolver and ClosureState.

## Invariants

1. Delta-first does not imply test skipping. Unknown/transitive code, scripts and workflow changes are semantic and expand verification.
2. Failure classification is fail-closed. UNKNOWN and authorization/provenance/schema failures route to minimum safe repair.
3. Infrastructure, runner, queue and external dependency failures are not mislabeled as code defects.
4. Evidence reuse requires identical source SHA, tree SHA, workflow identity, terminal PASS and no invalidation; CriticalPathPlanner itself rejects bare or mismatched PASS evidence.
5. Superseded runs do not block the current candidate; required terminal evidence is PROTECTED_EVIDENCE.
6. First two full CI runs fit the normal budget. Run three and later require one machine-readable FullCIReason.
7. CandidateFreeze blocks unreasoned cosmetic mutation after freeze.
8. Closure bundle is complete before manifest stabilization and freeze.
9. Independent review PASS cannot be generated by the builder.
10. HUMAN merge authorization is mandatory and non-configurable; callers cannot disable the gate.
11. Landing without post-landing PASS is not closure.

## Workflow topology

Stage14 assurance runs on pull_request to main, on main push for post-landing verification,
or exact workflow_dispatch. Ordinary feature-branch pushes do not create a second Stage14 full run.

The first candidate assurance may expose the canonical manifest delta.
The manifest is then synchronized once, candidate frozen, and final exact-SHA CI run once.

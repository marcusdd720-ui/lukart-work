# Stage 06 — Document Registry readiness and requirement matrix

Baseline: `b8bbe1be40690170c5bb2f400ca774e71952a352` (Stage 05 merged and post-merge CI GREEN).
This stage is synthetic CASE-TESTY only. No real CASE data, external filing, procedural analysis,
drafting, rendering, deployment or ROS runtime integration is in scope.

## Architecture decision

Stage 06 reuses the existing `Filing`, `SourceDocument`, Core transaction/CAS/audit/outbox and
PostgreSQL RLS boundaries. It does **not** add a `Document` entity or a second writable registry.
The minimum new boundary is `DocumentRegistryService` plus versioned typed request/receipt/query
contracts. Append-only registry receipts are stored in the existing case-scoped `lw_core.objects`
store. Current registry state is a deterministic projection of authoritative Filing revisions,
immutable sources and receipt history.

Content identity, Filing identity and receipt/event identity remain separate. Identical bytes may
back multiple legitimate Filings. A historical Filing revision cannot change its registered
artifact identity.

## Requirement matrix

| ID | Requirement | Initial state | Stage 06 control |
|---|---|---|---|
| S06-01 | Canonical Filing lifecycle | PRESENT | preserve existing closed transition allowlist |
| S06-02 | Immutable artifact/source binding | PARTIAL | registration receipt + source byte/hash verification |
| S06-03 | Registration identity/history | MISSING | append-only `RegistryReceipt` chain |
| S06-04 | SUBMITTED requires evidence | MISSING | `RecordSubmission` requires independent receipt source |
| S06-05 | ACKNOWLEDGED requires separate evidence | MISSING | `RecordAcknowledgement` requires a distinct source |
| S06-06 | Tenant/case/authority isolation | PRESENT/PARTIAL | reuse Core auth/RLS; HUMAN-only writes |
| S06-07 | CAS/idempotency/replay/rollback | PRESENT | reuse outer `CommandService.execute` transaction |
| S06-08 | Deterministic current-state projection | MISSING | read-only `RegistryProjection` |
| S06-09 | Backward compatibility | PRESENT | historical Filings remain unchanged and are reported as unregistered |
| S06-10 | Same bytes != same Filing | MISSING test | explicit duplicate-content/multiple-Filing test |
| S06-11 | Machine-readable evidence | PARTIAL | `reports/stage06-status.json` generated by runner |
| S06-12 | Global integrity | PRESENT | retain strict manifest coverage/hash checker |

## Threat / failure model

Fail closed on missing/tampered/tombstoned source bytes, stale Filing revisions, illegal lifecycle
transitions, missing submission/acknowledgement evidence, receipt reuse across Filing/CASE,
cross-tenant/case references, idempotency-key conflicts and non-HUMAN external-state writes.
Receipt presence does not establish truth of document contents or legal effectiveness.
`SUBMITTED != ACKNOWLEDGED != EFFECTIVE`.
